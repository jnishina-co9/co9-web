Solution

無機質な仕様書を、AIで『誰でも読めるHTML』に変える仕組みづくり

自作ツールを作るたびに、内容だけでなく見た目まで毎回デザインし直すのは、思いのほか手間のかかる作業でした。そこで、「Markdownテンプレート」と「HTML変換指示書」をあらかじめセットで用意し、AIに渡すだけで見やすい仕様書ページが自動生成される仕組みを作りました。これにより、作る人はプロンプト一つで完結でき、読む人にとっても分かりやすい仕様書を実現しています。

Specification

仕様

技術スタック
HTML / CSS / JavaScript
動作環境 生成AI(Claude、ChatGPT、Antigravityなどのチャット・AIツール)にMarkdownファイルを読み込ませ、HTML変換を依頼できる環境。完成したHTMLはモダンブラウザ(Chrome・Edgeなどの新しいブラウザ)で動作し、インストールは不要
制約・スコープ外 バックエンド(サーバー側の処理)やデータベースは持たないため、仕様書のデータが外部サーバーへ送信・保存されることはありません
Concept

書くのは、ひとこと「仕様書を書いて」だけ。

AIにこのテンプレートと変換ルールを読み込ませておけば、あとは一言、「書いて」とお願いするだけ。ツールの中身を読み取って文章を書き起こし、配色・文字サイズ・余白まで指示書通りに整えたHTMLへ、一度の会話でそのまま仕上げてくれます。

01

テンプレートと指示書を分離

書き起こしのテンプレート(spec.md)とデザインの指示書(spec-html.md)を別ファイルに分けることで、AIが文章とデザインの両方を迷わず進められます。

02

項目数は自由に増減可能

機能の数や処理フローのステップ数は固定ではありません。アプリの規模に合わせて、AIが柔軟に項目を追加・削除します。

03

実際のコードから書き起こすから、仕様と実装がズレない

手作業の仕様書はコードの変更に追いつかず古くなりがちですが、AIがそのつどアプリの中身を読み取って書き起こすため、実態と乖離しません。

04

1ファイル完結・外部送信ゼロ

生成されるHTMLはCSS・JSも1ファイルに埋め込まれた静的ページ。サーバーとのやり取りもデータ送信も発生しません。

Features

主な機能

1AIが迷わず書けるMarkdownテンプレート

「基本情報」「主な機能」「処理フロー」など8項目の構成があらかじめ決まっているので、AIに一言頼むだけで抜け漏れのない仕様書に仕上がります。

2デザインを統一するHTML変換指示書

配色・文字サイズ・余白・レスポンシブ対応まで定義済みの指示書。AIに読み込ませるだけで、毎回同じ品質のデザインに仕上がります。

3快適に読めるナビゲーション＆アコーディオン

セクションごとに開閉できるアコーディオンに加え、読んでいる位置に合わせてハイライトが動くサイドバー目次、進捗バーとトップへ戻るボタンまで搭載。長い仕様書でも迷わず読み進められます。

4そのまま資料として配れる印刷・PDF出力対応

印刷時はサイドバーや操作ボタンを自動で非表示にし、そのままPDFとして保存できる専用レイアウトに切り替わります。

Flow

処理の流れは3ステップ

  1. 01

    「仕様書を書いて」とAIに頼む

    プロジェクトにspec.mdとspec-html.mdを置き、対象のツールについてAIに一言依頼します。

  2. 02

    AIがコードを解析し、自動でHTML化する

    アプリのコード(HTML・JavaScriptなど)を読み取って機能や使用技術を解析し、spec.mdのテンプレートに沿って専門用語には( )付きの解説を添えながら内容を書き起こします。続けてspec-html.mdのデザインルールに従い、1ファイル完結のHTMLに変換します。

  3. 03

    ブラウザで確認・公開する

    生成されたHTMLをそのままブラウザで開いて確認。問題なければGitHub Pagesなどにアップロードしてそのまま公開できます。

UI / UX

使いやすさの工夫

配色は4色に絞り、アクセントは矢印だけに限定

配色はメイン・ベース・サブ・アクセントの4色に固定し、差し色はアコーディオンの矢印だけに限定。誰が生成しても統一感のある見た目に仕上がります。

バグが起きやすい動きは「正解コード」を埋め込み

目次のハイライト表示など不具合の起きやすいJavaScript(動きをつけるプログラム)は、AIに作らせず「正解コード」を指示書に記載。実装のズレをなくし、毎回同じ操作性を実現します。

専門用語には「( )で解説」をつける自動ルール

APIやCDNなどの専門用語には( )で説明を添えるルールを指示書に明記。非エンジニアやクライアントにもすんなり読める仕様書に仕上がります。

配布・共有が一番ラクな「1ファイル完結」設計

デザインもプログラムも1つのHTMLファイルに埋め込む設計。ファイル不足のトラブルがなく、チャットやメールで送ってダブルクリックするだけで誰でもすぐ閲覧できます。
